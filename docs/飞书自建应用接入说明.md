# 飞书自建应用接入说明

当前采用官方 `lark-oapi==1.7.5` SDK的**长连接独立进程**，无需公网回调地址。飞书是消息入口，现有后端仍负责Agent调用、状态校验和业务写入。

```text
飞书用户单聊 → SDK长连接 → 本地收件队列 → 8003业务API
                                              ↓
飞书文本回复 ← SDK回复接口 ← 企服Agent初审 / 人工确认建单
```

选型见[ADR-005](./architecture/ADR-005-飞书长连接桥接.md)，文字报修进展见[验收记录](./verification/20261101-飞书长连接接入.md)。本人真实单聊配对、追问、千问补项、确认建单和进度已验收通过，业务资料为模拟数据；新增工程卡片及维修反馈见下节6，企服飞书验收仍未接入。

## 1. 飞书控制台

在[飞书开放平台](https://open.feishu.cn/app)打开企业自建应用：

1. “应用能力 / 添加应用能力”中启用**机器人**。
2. “权限管理”申请接收单聊消息 `im:message.p2p_msg:readonly`、以应用身份发消息 `im:message:send_as_bot`。
3. “事件与回调”中将事件订阅方式设为**使用长连接接收事件**，订阅 `im.message.receive_v1`。不填写Webhook请求地址；如果控制台要求先建立连接，可先启动下面的桥接命令再保存。
4. “版本管理与发布”创建版本，将可用范围包含本人并发布。若租户要求管理员审批，完成审批后权限才生效。
5. 飞书客户端搜索应用名称，打开机器人单聊；也可从工作台打开应用后进入机器人。

菜单名称可能随控制台版本调整，配置对象和权限标识以上述内容为准。

## 2. 本机配置与启动

在已有 `backend/.env` 中配置以下字段，不把实际值发到聊天或写入仓库。终端环境变量优先于文件，修改后只重启桥接即可更新飞书凭证。

```dotenv
FEISHU_APP_ID=你的企业自建应用AppID
FEISHU_APP_SECRET=你的企业自建应用AppSecret
# 可选：逗号分隔的本人测试账号open_id。不配置时用单次配对码绑定本人。
FEISHU_ALLOWED_OPEN_IDS=
```

项目根目录执行：

```powershell
# 首次安装或依赖变化时执行
& .\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
# 只检查凭证、真实鉴权和隔离演示标记，不监听或发消息
& .\.venv\Scripts\python.exe backend\scripts\run_feishu.py --check
# 启动桥接；8003必须已在运行，不要为此重启现有内存演示后端
& .\.venv\Scripts\python.exe backend\scripts\run_feishu.py --backend-url http://127.0.0.1:8003
```

出现 `{"feishu_connection": "connected"}` 表示连接已建立，**不代表消息订阅、回复权限或业务流程已验收**。保持该进程运行，Ctrl+C只停止桥接，Web和后端继续工作。单实例锁避免同应用在本机重复启动。

脚本仅接受 `127.0.0.1` HTTP地址，并检查后端是 `isolated_demo` 模拟数据环境。当前5174页面代理8003，机器人与该页面共用业务数据。桥接不会启动后端、执行业务迁移或删除数据。

## 3. 配对及报修

首次启动在终端显示6位配对码，10分钟有效。在本人机器人单聊发送 `绑定 <本次配对码>`。收到回复后：

1. 发 `报修 漏水`，应收到补充位置的追问，此时没有工单。
2. 发 `位置在A栋302`，应显示完整草稿和人工确认提示，此时仍没有工单。
3. 核对位置、故障和描述后，发 `确认普通`、`确认加急`、`确认特急`之一，中间也可加空格或冒号。只有明确确认才建单。
4. 发 `进度` 或 `状态`，查询本人当前报修；工单可在5174的维修工作区查看。
5. 发 `新报修 位置和故障描述` 开启另一流程；发 `帮助` 查看指令。

未配对账号及未授权消息不调用模型、不写业务、不回复。配对码不存入收件消息；绑定只提供隔离演示报修权限，不提供工程派工或企服验收权限。配对关系在本机缓存，正常重启不重复配对；新增或变更测试账号可配置明确允许名单，优先于原配对关系。

“确认”单独发送不会执行建单。“普通 / 加急 / 特急”单独发送只提示进一步明确确认，不写入故障描述、不调用补项模型。确认指令按整条消息匹配，“确认普通吗”等含糊表达不建单；缺项仍需先补齐。模型成功显示通义千问及模型名；失败按实际结果显示规则回退。AI检查信息完整性，不代替人工核对、不批准或拒绝报修、不自行决定优先级。

更新桥接后，旧版已处理且回复“没有执行建单”的消息不会被自动重放，需本人重新发送确认。原草稿和历史消息保留，修复不追溯删除此前误写入的内容。

## 4. 状态及诊断

另一终端可执行：

```powershell
& .\.venv\Scripts\python.exe backend\scripts\run_feishu.py --status
```

仅输出配对情况、连接状态、队列计数和受控错误码，不输出凭证、open_id或消息正文。`done`表示回复接口成功；`queued`表示待执行或等待重试；`failed`表示连续3次失败，需要排查。停止异常时缓存的connection可能是旧值，应同时核对桥接进程是否仍运行。

| 现象 / 错误码 | 检查方式 |
| --- | --- |
| 已connected但没有回复或收件计数 | 核对发布版本、可用范围、单聊消息事件、接收权限及配对码；图片和群聊不受理 |
| `feishu_credentials_missing_or_invalid` | 本机检查.env字段，勿复制凭证到聊天 |
| `feishu_auth_*` / `feishu_auth_network_error` | 核对企业自建应用凭证和网络 |
| `feishu_api_<数字>` | 对照飞书官方接口错误码核对发送权限、机器人能力和发布状态，不输出原始SDK响应 |
| `business_unavailable` / `business_http_*` | 检查8003是否仍运行及API状态，不盲目重启内存库 |
| `isolated_demo_required` | 当前后端不是本轮允许的隔离演示环境 |
| `workflow_owner_mismatch` | 会话身份校验失败，停止处理并排查映射，不放宽校验 |
| `bridge_already_running` | 已有本机桥接占用锁，使用原进程，不重复启动 |

状态保存在已忽略的 `backend/.local/feishu-<应用摘要>.sqlite3`，与业务库分开，包含本人会话映射、已授权消息正文及回复缓存。它属于本机运行数据，勿提交、打包公开或当作业务备份；日志不打印原始SDK连接URL、token或消息正文。正式部署前需配置访问控制、保留期限及失败告警。

收件按message_id去重，业务动作使用稳定幂等键；回复失败只重发已保存的回复。同会话重试保持顺序，最多尝试3次。若业务演示后端重启，缓存流程可能失效，机器人会提示重新报修，不自动关联其他流程。

## 5. 当前边界与旧Webhook入口

前一阶段通过本人单聊**文字报修、补项、明确确认和进度**验收。新增工程卡片及维修照片反馈按下节独立验收；企服验收继续在Web办理。群聊、招商对话、生产级部门权限、超时提醒仍未接入。

旧 `POST /api/v1/integrations/feishu/events` 保留原Token/签名校验和文本转流程功能，不承担本轮长连接收发。`FEISHU_VERIFICATION_TOKEN`、`FEISHU_ENCRYPT_KEY`仅属于旧Webhook路径，长连接不需要填写，也不需要公网隧道。不要同时按两套接收方式配置本轮应用。

## 6. 新增工程派工卡片与维修反馈

选型：[ADR-006](./architecture/ADR-006-飞书工程派工与维修反馈.md)。用户已选择本人分别演示工程负责人和空调维修模拟员；此授权仅用于isolated_demo，不等于真实组织权限。

开放平台“事件与回调”添加**卡片回传交互 `card.action.trigger`**，继续使用长连接；保留已有`im:resource`，并增加**`im:message:readonly`**，创建新版本并发布，必要时完成管理员审批。实际GetMessageResource曾返回99991672，要求im:message/im:message.history:readonly/im:message:readonly之一，仅开im:resource不足；本项目采用im:message:readonly。本机原失败图片已只读复验成功。原单聊收发权限保留。

停止旧桥接后，从项目根目录启动，保留原8003后端：

```powershell
& .\.venv\Scripts\python.exe backend\scripts\run_feishu.py --backend-url http://127.0.0.1:8003 --demo-engineering --demo-personnel ENG-DEMO-001
```

只对已配对本人显式启用两个模拟角色；不需要重新配对。省略工程演示参数可回到原报修权限。新增 `--engineering-identities <本机JSON路径>` 用于不同账号演示，不能与本人角色演示参数混用。文件放在已忽略的backend/.local下，不提交真实open_id：

```json
{
  "ou_负责人占位": {"roles": ["dispatcher"], "actor_id": "MANAGER-DEMO"},
  "ou_维修员占位": {"roles": ["technician"], "actor_id": "WORKER-DEMO", "personnel_no": "ENG-DEMO-001"}
}
```

上例为结构说明，占位标识不能直接运行。实际open_id仅在本机填写；同一人员编号不能绑定两个维修账号。未绑定飞书维修角色的人员仍显示在候选中，但需转Web办理，不伪造任务送达。

本人演示步骤（沿用2号模拟工单）：

1. 发 `派工 2`，查看工程Agent的真实运行模式、理由与候选；此时不产生分派。
2. 点击空调维修模拟员的**确认委派**按钮，确认操作。机器人记录分派并排队发送维修任务卡；发送成功不等于已接单。
3. 在维修任务卡点击**确认接单**，任务卡更新后点击**开始维修**。需要刷新时发 `维修 2`，`维修2`也可。
4. 工单进入processing后，本单聊已选择该工单作为反馈上下文；可直接发送“漏水已维修完毕”等实际处理说明，再发送模拟现场图片，顺序不限。说明与成功照片分别保存，照片失败不丢弃已保存说明。每次最多5张，单张10MiB，静态JPEG/PNG/WebP；后端会重新编码校验，不进行AI识图。
5. 材料齐全后自动展示说明及照片数量预览；原`维修反馈 2 简短说明`入口仍可用。图片因权限或网络失败时，修复后发`重试照片`读取原消息，无需重复上传。无照片不提交，原文说明不可由模型编造；更正说明重新生成预览，旧按钮失效。发送`进度`只查询状态，不调用模型。
6. 点击**确认提交维修结果**，成功后进入pending_review；原飞书报修人收到待企服验收通知，Web可查看维修说明及实际照片。工程人员不能直接关闭，企服继续在Web验收或退回。

不清除此前草稿、历史或工单。开始“报修/新报修”会退出旧维修图片上下文；重新选择维修对象请发 `维修 工单ID`，避免把不同任务图片混在一起。未绑定人员、错误操作者、转发卡片、过期或已变更状态的卡片会拒绝；同一动作重复点击不重复执行业务。

按钮15分钟有效。同一任务/预览按已保存message_id更新原卡片，旧nonce失效；已知消息ID的旧按钮卡改为只读历史。旧版本未记录消息ID的纯展示卡无法追溯更新；发`维修 2`获取当前有效任务。卡片更新失败独立重试，不重复执行业务。SDK回调快速入队，提示“已收到”只表示消息已收取，最终以卡片及业务API结果为准。`--status`包含engineering jobs/outbox和受控错误码，失败发送最多3次；`blocked`动作需先查询实际工单再刷新，不能手工批量重放。实现及边界见[ADR-007](./architecture/ADR-007-维修上下文与反馈整理.md)。

当前仅复用旧附件API上传，附件表source_channel仍沿用该入口默认web，桥接本地记录保存实际飞书图片消息来源；不能据该字段声称完成渠道审计升级。旧业务API还没有部署级鉴权和完整幂等/条件更新，因此仅用于本机隔离演示；回调重复保护不等于已消除与Web并发操作的所有竞态。特急5分钟电话升级、企服飞书验收卡、报修图片和多模态识图仍是后续范围。

## 7. 自动提醒（ADR-008新增）

用户已授权本人继续兼任模拟招商负责人。停止旧桥接后运行：

```powershell
$env:PARK_AI_MODE='qwen'
& .\.venv\Scripts\python.exe backend\scripts\run_feishu.py --backend-url http://127.0.0.1:8003 --demo-engineering --demo-personnel ENG-DEMO-001 --reminders --demo-investment-owner '招商演示员'
```

保留8003，勿重启有现有资料的内存后端。新增参数只启用本次进程，不写.env。默认独立线程每30秒扫描，允许--reminder-interval 5至300秒；提醒本身不调用模型，不修改工单、客户、回访及其到期日。省略--reminders即可停用主动提醒，正常报修和工程功能保留。

| 场景 | 触发及接收人 |
| --- | --- |
| 工程新工单 | pending且未接单，自动发给显式绑定的工程负责人；负责人仍须核对Agent建议并确认派工 |
| 招商回访到期 | due_at已到且任务仍pending，只发给owner与--demo-investment-owner精确匹配的本人；其他owner不自动映射 |
| 普通/加急接单超期 | 后端Demo SLA接单期限到期，通知负责人及已映射的当前维修员 |
| 处理超期 | accepted/processing且未提交结果，处理时限已到，通知负责人及已映射维修员 |
| 特急5分钟未响应 | 本机制向该工程负责人发送新单通知成功后满5分钟仍未接单，提醒电话对接；失败/缺回执不以建单时间替代 |

每个任务/阶段/接收人首次触发一次，已发送回执持久化，重启不重复轰炸。发送前再次核对状态与接收人，完成/签约取消/已接单/已提交/角色撤销的旧通知会取消。失败最多3次退避重试且复用同一UUID；最终failed需要查看受控错误码并排查，不自动重做业务动作。

--status新增reminders投递计数、last_scan_at、unmapped_count和scan_error。sent表示飞书发送接口成功，不是已读；cancelled表示发送前业务条件已失效。定时检查受API耗时、网络和进程运行影响，不保证严格准点；本机单实例不能替代生产高可用部署。

旧手动/api/v1/escalations/scan仍是按建单时间计算的原型业务待办接口；本轮自动提醒不调用它，也不以其结果表示推送后5分钟已验收。真实回执当前保存在独立渠道账本，业务端统一回执与电话结果处理仍待后续整合。

可选--reminder-self-test仅给已配对本人发送标注“模拟测试”的联通消息，不改变业务时限、不写业务发送回执；须先停止原桥接，测试退出后再正常启动。

## 8. Web操作后继续飞书查询

Web与飞书读取同一业务状态。负责人发送“派工 ID”：未分派且待接单时获取工程Agent建议；已有分派或进入后续处理时查看当前维修员与实际状态。本人也是当前维修员才显示维修操作卡；已在Web派给其他人的工单不能由当前账号冒用身份操作。

启用--reminders时，默认30秒扫描同时同步Web分派、接单、处理及完成状态。给已绑定的当前维修员更新任务卡；未绑定人员则向负责人提示继续在Web办理或由管理员明确配置账号映射。改派后原维修员的操作卡停用，材料上下文失效；收到processing同步卡后先发送“维修 ID”选择材料工单，避免多任务图片串单。

只反映扫描时最新状态，业务中间过程仍以API事件记录为准。历史文本通知作为历史记录保留，最新卡片显示当前状态。当前演示本人仅绑定ENG-DEMO-001；Web分派ENG-DEMO-002后负责人可查询其进度，但不自动获得002的维修权限。详见[ADR-009](./architecture/ADR-009-Web与飞书工程状态同步.md)。
