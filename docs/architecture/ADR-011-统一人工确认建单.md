# ADR-011：统一人工确认建单

- 日期：2026-11-09
- 状态：已验证（离线回归与前端构建）
- 范围：普通建单、Web/飞书协同确认、页面提示及回归测试。

## 问题与决定

普通建单按关键词自动提高优先级，协同确认建单保留人工选择，导致同一确认结果因入口不同而改变。复用现有 `create_ticket_from_confirmed()`，统一保存人工确认的优先级、生成编号及创建事件。

保留两个入口各自的建单逻辑会继续造成规则分叉；让全部入口自动提高等级则违背已确认的人工决策规则。采用公共业务服务，入口保留附件绑定、流程记录及来源差异。

## 边界与事务

模型和规则仅提供建议，页面核对后提交最终等级。公共服务不提交事务，普通接口负责把工单、创建事件和附件绑定一起提交或回滚。协同流程沿用现有事务和幂等门禁。默认普通等级保持兼容。生产身份认证、编号并发及普通接口幂等不在本次范围，不迁移或修改既有数据。

## 实施与验证

已调整普通建单接口复用公共服务，并更新页面文案。

- 后端离线全套回归：269 项通过（105.59 秒），保留 2 条第三方飞书 SDK 弃用警告。
- 新增 6 组参数化检查：三种确认等级 × 两种描述，覆盖普通、Web 及飞书来源流程 API 的确认结果、初始状态、创建事件及来源差异；旧自动升级用例已改为验证保留人工确认等级。
- 现有附件绑定失败回滚、协同确认幂等、飞书桥接测试随全套回归通过。
- 前端 `npm run build`：类型检查与构建通过。
- 未调用真实模型、未操作真实飞书客户端、未进行浏览器视觉验收；渠道一致性检查属于隔离 API 测试。未重启正在运行的内存演示后端，新后端规则需重新加载代码后生效。

## 授权与依据

用户已确认“建议由人核对，后端保存确认结果”，并明确要求实施。依据本仓库 PRD、ticket_service.py 和 workflow_service.py 的现有人工确认设计。撤销时可恢复普通接口旧规则，但会重新引入入口差异。
