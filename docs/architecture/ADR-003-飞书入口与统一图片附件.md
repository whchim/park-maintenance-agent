# ADR-003：飞书主入口、Web运营演示与统一图片附件

- 日期：2026-11-01
- 状态：本机隔离演示已实现并验证；真实飞书接入待实施
- 需求：报修和维修反馈支持拖拽图片，为飞书机器人消息复用后端能力。

## 业务背景与入口取舍

用户描述了上一家公司的试运行经历：为了对外展示转向小程序，但员工实际使用较少。这是本项目的需求背景，不能据此推导所有小程序均不可行。当前选择让园区员工在已有飞书办公场景接收任务、提交文字和图片；Web用于运营维护、流程追踪、测试与对外演示。演示复用同一业务API，不要求实际使用者切换到Web。

企业知识库适合提供制度和检索依据，但不能代替工单状态、分派、事务、幂等和审计。继续采用“飞书渠道适配 → 园区后端流程与附件服务 → Agent智能协同”，运营Web调用同一套服务。机器人派发和卡片反馈是后续飞书集成工作，本轮不宣称已经上线。

## 备选与决定

| 方案 | 成本与边界 | 决定 |
| --- | --- | --- |
| 仅浏览器本地预览/base64放进业务JSON | 刷新失效或请求膨胀，不能供其他渠道复用 | 不采用 |
| Web与飞书各存一份附件 | 关联和权限分散，不利于业务追溯 | 不采用 |
| 统一附件元数据+本地受控文件存储 | 需要新增一张表，适合本机单实例；未来可换对象存储 | 本轮采用 |
| 直接引入对象存储/消息平台 | 适合部署阶段，当前需额外账号、权限和运维 | 后续评估 |

上传采用单张原始二进制HTTP请求（文件名为独立查询参数），避免base64膨胀；当前没有其他表单字段，无需额外multipart解析依赖。引入Pillow验证并重新编码JPEG/PNG/WebP，过滤伪装文件、破损图和过大像素，去掉EXIF等附加元数据。每张最多10MiB、2000万像素，每次业务提交最多5张，禁止SVG/GIF及动画图。输出也限制10MiB。

## 责任与事务

- 上传先得到随机附件ID，仅保存文件及元数据，不创建工单、不调用模型。元数据记录来源、用途、摘要和业务关联；不信任客户端文件名作为路径。
- 报修附件在受理/补充时绑定流程，人工确认后同步绑定工单；维修图随维修记录在业务事务中绑定。绑定失败回滚，禁止跨流程/工单复用或篡改已提交维修证据。
- 暂存附件24小时内可绑定；前端“移除”仅取消本次选择，不删除服务端资料。未绑定文件本轮不自动清理，后续由有审计的维护任务管理，避免误删。
- 文件与SQL没有分布式事务：写库失败清理本次新写文件；业务失败保留暂存附件便于重试。部署后的崩溃遗留清理由后续维护机制处理。
- 演示使用实例自己的临时文件目录，与内存数据库同生命周期；正式附件表仅提供增量脚本，本轮不执行现有库迁移。普通入口使用固定backend/var/uploads路径，纳入忽略规则，不静态暴露目录。
- 新接口处于现有本机演示鉴权边界，随机ID不等于用户授权。对外部署前须完成登录、飞书open_id映射、部门/工单附件权限、配额与存储策略。当前仅监听本机，不增加公网暴露。

## AI与飞书边界

本轮图片仅作为现场/维修证据展示，**不会发送给千问，不做视觉识别**。仅发图仍需补充位置和故障文字，图片不能绕过人工确认。未来多模态Agent读取同一附件ID，需单独验证视觉模型、成本、授权及不确定性处理，不能通过“已上传”暗示“已理解”。

飞书后续适配应在验签及身份映射后，用机器人凭据获取消息图片，经相同图片校验服务入库，记录飞书消息/图片键，再交给统一流程；不接受任意远程URL抓取，不在业务Service持有飞书凭据。当前飞书回调仍只处理文本，本轮不伪造真实图片接入。

## 验证计划与参与点

验证伪造/破损/超限/路径穿越、媒体读取、附件跨业务绑定拒绝、失败回滚、补项与确认门禁、维修图片保存及刷新回显；使用独立内存数据库及临时目录。浏览器验证选图、拖放事件、预览、移除与提交，不调用真实模型识图。实施后回填结果。

回填：后端全套155项通过，附件及演示20项，前端类型检查/生产构建与依赖检查通过。浏览器完成点击选图、移除、纯图追问、文字补项确认、手动建单、维修反馈提交和刷新后图文回显；操作系统拖拽手势留给用户人工检查，不能写成已自动化复现。联调增加空轨迹兼容及演示共享连接互斥；截图、命令和未验证边界见[图片上传验收](../verification/图片上传与飞书入口验收.md)。未执行现有库迁移；飞书图片下载和AI识图未实现。

用户参与：用模拟现场图片测试报修和维修反馈，评估飞书中所需的最少输入；后续确认照片是否业务必填及保留期限。本轮照片为可选，不替业务制定强制留证制度。

后续试用应记录从收到任务到有效反馈所需的操作步数、是否重复填报、响应/反馈完成率和人工纠错情况；先取得业务基线，再比较飞书入口效果。对外演示展示同一流程的责任、时限、建议依据和人工确认，不以新建入口或增加Agent数量代替使用价值。

依据为本项目代码与用户反馈；新增Pillow能力需通过项目测试验证，不以库支持某格式代替已集成视觉Agent。
