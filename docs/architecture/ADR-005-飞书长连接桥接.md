# ADR-005：飞书企业自建机器人长连接桥接

- 日期：2026-11-01
- 状态：本人真实单聊报修、追问、补项、人工确认建单及进度查询验收通过（模拟业务数据）
- 范围：本机企业自建应用单聊，报修受理/补充/确认和进度查询；复用现有隔离演示后端，不重启8003或迁移业务库。

## 1. 具体问题与约束

用户已创建企业自建应用并在本机配置App ID和App Secret。当前只有Webhook文本事件适配，缺少真正的机器人接收、回复及跨消息续办。当前8003是有已验收资料的内存库，不能为新增接入重启清空；Web后端没有部署级鉴权，不应暴露到公网。

## 2. 备选与取舍

| 方案 | 收益 | 成本与边界 | 决定 |
| --- | --- | --- | --- |
| Webhook加HTTPS隧道 | 复用现有回调路径 | 暴露未完成部署鉴权的本机业务服务，另需处理回调超时及公网入口 | 本轮不采用 |
| 长连接放入现有后端启动生命周期 | 同进程可用业务Service | 要重启当前内存库，SDK生命周期与API耦合 | 后续部署再评估 |
| 官方SDK长连接独立桥接进程 | 无公网入口、保留后端进程和数据、复用业务API | 本地需要额外进程及收件去重状态 | 本轮采用 |

采用官方`lark-oapi==1.7.5`，版本和依赖取自官方PyPI元数据。其WebSocket协议和token管理由SDK负责，不自行实现长连接协议。

## 3. 决定与分工

飞书SDK收事件 → 本地桥接收件/去重 → 串行工作线程 → 127.0.0.1业务API → 原Agent/Service → 飞书回复。接收回调快速入队，不在SDK回调线程等待模型。关键动作仍由用户明确发送确认指令，优先级显式选择；机器人不自动分派或验收。

桥接仅接受单聊、真实用户消息，按飞书message_id去重。会话按chat_id和open_id隔离，不能以工单号猜测方式访问其他人的流程。初次测试采用本机配对码绑定当前单聊用户，或本机明确配置允许的open_id；不默认为全企业开放，也不把open_id当作工程/企服权限凭证。配对仅提供本轮演示报修提交权限。

## 4. 持久化及失败边界

桥接状态文件放在已忽略的`backend/.local/`，与业务SQLite分开；只保存本轮渠道续办、收件去重和回复状态，不建模客户、工单或人员。接入脚本只连接显式指定的127.0.0.1隔离演示后端，并检查runtime标记。

业务API的消息/确认动作使用稳定幂等键；已执行但回复失败时可重试回复。工程建议和模型结果仍以业务API为准，日志不输出消息正文、SDK原始响应、凭证或token。桥接与演示内存库的生命周期不同，恢复时需要检查流程仍存在，不能把旧缓存误认成当前已完成业务。

## 5. 实施与退出

先完成文本单聊、会话隔离、明确确认与进度查询，验证去重、失败与授权边界，再连接真实应用。图片资源、群聊、真实部门身份、工程派发/维修反馈卡片和招商入口按后续范围扩展；本轮未通过验收的能力不得写为已接入。

停止桥接进程即可关闭长连接，现有Web和业务后端继续运行；不删除业务数据。部署阶段再评估独立worker、持久化业务库、细化部门权限与飞书卡片。

## 6. 验收

当前结论：用户复测确认收到工单编号且进度正常，后端只读核对为 `WX202611010002`、normal、pending、未分派，飞书会话归属匹配，原1号工单完整公开响应hash保持一致。本人单聊文字报修建单链路通过；不包含飞书工程派发/维修反馈/企服验收及生产部署验收。

第二轮：用户已确认配对和追问，截图证实真实千问补项草稿。已修复无空格“确认普通”无法识别、单独“普通”污染故障描述的问题，不改变人工确认与优先级门禁；桥接40项、后端196项回归通过。仅重启独立桥接并恢复connected，8003及原配对保留，原工单/交接/飞书流程前后hash一致。真实确认建单及进度的后续复测结果见上述当前结论。此次是原方案内输入解析修复，无新增架构选型。

首轮2026-11-01：官方SDK安装及pip依赖检查通过；22项桥接测试、178项后端回归通过。真实tenant鉴权通过，SDK已报告长连接connected，连接当前8003隔离演示后端。用户已确认应用发布，当时实际收件/回复待验，后续结果见当前结论。

桥接测试使用真实业务API和独立内存库，覆盖缺项追问、明确优先级确认建单、重复确认、进度、事件去重、回复失败不重复执行业务、同会话顺序、重启续发、身份隔离与撤权、过期配对、非演示后端拒绝、旧流程失效、单实例锁和日志脱敏。配对与成功消息入队在一个本地事务完成。失败最多尝试3次，此后标为failed并通过本机状态命令暴露，不宣称必达；下一条消息可继续，操作者需先检查状态。

本地队列保证可恢复和幂等重试，不是跨飞书与业务API的分布式事务。回复使用稳定uuid降低重发重复风险，仍受飞书接口去重期限约束。正式部署仍需告警、失败消息处置及保留策略。详见[飞书验收记录](../verification/20261101-飞书长连接接入.md)。

## 7. 用户参与

用户在飞书控制台启用机器人、长连接事件订阅与收发消息权限，并发布到本人可用范围；凭证只写本机环境文件。随后在机器人单聊发送配对及模拟报修。需要用户真实飞书操作的地方保留参与，不让其逐项审批内部实现。
