# ADR-010 新报修续办与 Web 自动刷新

- 日期：2026-11-01
- 状态：已实现，后端263项、前端构建与8个合成同步场景通过；真实客户端自动刷新效果待本人核对
- 问题：单独发送“新报修”只提示补项而保留旧工单会话，后续文字仍查询旧单；Web 仅手动刷新，不能主动反映飞书操作。

## 决定

将“新报修”原始消息作为新受理流程的初始输入，复用现有缺项分支及会话映射。只建立待补充草稿，不创建工单；后续仍需补项、人工确认优先级。相比新增渠道待输入表或特殊会话标记，复用已有 WorkflowSession 可避免重复状态来源及迁移。旧工单和事件不变，旧消息不自动重放。

Web 在维修工作区可见时每 5 秒只读刷新列表、当前工单事件和凭证；窗口重新聚焦、页面重新可见及切回维修区时立即检查。后台刷新不显示整页加载、不清空输入，不调用模型或业务写接口，失败显示重试提示。使用请求序号及工单编号隔离过期结果，卸载时释放定时器和监听。

暂不引入 SSE/WebSocket：本机演示只需少量只读轮询，推送会新增后端连接管理并要求重启当前内存实例。保留手动刷新按钮；5 秒为轮询间隔，不保证网络条件下严格实时。

## 验证计划

用隔离 API 复现“旧单已创建 → 新报修 → 确认前补项 → 新单确认”，核对旧单保持、缺项不建单与重试不重复。前端检查后台刷新、切换工单、输入保留与事件释放，运行类型检查和构建。只重启飞书桥接，不重启 8003，不迁移业务库。同步更新提交源码包和录屏说明，避免交付旧版本。

## 实施证据

新增3个参数用例，最终后端263项通过。前端构建通过，直接执行App.vue脚本的8个合成网络场景通过；包括未提交材料保留、后台暂停、聚焦/工作区刷新、过期列表与详情隔离、卸载资源释放。5174实际提供的App.vue已包含自动同步逻辑。飞书桥接重新connected，保持本人001及招商提醒映射；8003未重启。

用户在本轮期间另建4号A栋302并推进至processing/ENG-DEMO-001，故总工单数由3变4，不将总列表hash变化误判为数据丢失。原1/2/3号摘要保持，客户与交接完整列表hash保持。4号存在及当前状态经只读API核对；单独“新报修”后续办、Web客户端自动刷新还没有本轮本人确认，不预写真实端验收通过。见[修复记录](../verification/20261101-飞书新草稿与Web同步修复.md)。
