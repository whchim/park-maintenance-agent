# ADR-007：按当前维修上下文受理自然语言及恢复失败照片

- 日期：2026-11-01
- 状态：已实施，真实单聊维修提交至待企服验收阶段通过
- 范围：修复ADR-006真实飞书验收暴露的会话断裂、照片权限、卡片与AI标识问题。

## 1. 问题及证据

用户已完成2号工单派工、接单和开始维修。照片资源读取返回99991672，官方实际响应要求im:message/im:message.history:readonly/im:message:readonly之一；此前仅提示im:resource不完整。随后“漏水已维修完毕”因不匹配固定指令落入旧报修回复，且错误复用初审模型标签。后端仍processing、维修记录0条，未通过维修提交验收。

## 2. 备选与选择

| 方案 | 收益与边界 | 结论 |
| --- | --- | --- |
| 增加几个结束关键词直接提交 | 简单但误解意图会写入业务，照片失败也可能误提交 | 不采用 |
| 全消息交给自主模型选择写工具 | 路由灵活但扩大模型权限，缺乏现有接口幂等及部署鉴权 | 不采用 |
| 当前任务确定性绑定+LangGraph结构化反馈整理+人工确认 | 工单/操作者由服务端确定，模型仅理解文本，材料按真实附件检查 | 采用 |

## 3. 决定及责任

沿用LangGraph和现有run_structured，不引入新框架。当前会话有明确维修上下文时，普通文本进入工程反馈图；新报修、帮助、配对等入口保留。入队时冻结工单和快照，工作线程再次校验当前分派/状态；不能因稍后切换工单而把旧图片或说明写到新单。无上下文不猜测工单。

图节点：理解维修反馈意图/原文说明→按真实已保存照片检查材料→等待补充或人工确认。模型只能输出意图、来自用户原文的说明与证据，不具有业务写工具；照片不做识图，用户声称修好不代表系统核验维修效果。规则回退如实标记，进度查询明确未调用模型。

说明保存在独立渠道草稿，缺照片也保留；照片成功后续接草稿，不要求重新写口令。失败照片可由用户发送“重试照片”恢复读取原消息，仍验证当前身份及所选工单，不自动重放业务写请求。

## 4. 卡片及恢复

新增渠道草稿和卡片视图引用，不迁移业务库。当前任务卡和预览卡按已保存message_id通过SDK patch更新，旧动作nonce失效；旧版本有已知message_id的按钮卡会改成只读历史提示。旧版本未保存message_id的纯展示卡不能承诺追溯更新。消息发送/patch失败独立重试，不重新执行业务。

权限错误提示具体恢复方法，说明照片未保存、工单未提交。用户已确认新增im:message:readonly并发布；必须重新读取实际原图片确认生效，不能凭配置答复当成功。

## 5. 验收与退出

覆盖自然语言反馈、文本先于照片、失败照片重试、切换上下文后的在途消息、越权与改派、模型原文依据/回退、无自动提交、中文状态、查询无新模型标签、卡片patch与旧按钮失效。保留原8003及原资料，只重启桥接；用户亲自确认维修预览才进入pending_review。真实照片、反馈模型、patch和最终业务状态分别记录，不预写通过。
