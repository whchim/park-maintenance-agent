# ADR-004：Web 业务工作区导航与草稿保留

- 日期：2026-11-01
- 状态：已实现，构建与运行时状态检查通过；浏览器交互待验证
- 对应需求、影响范围：维修协同、招商客户、客户交接改为同级工作区；只调整前端组织，不更改业务 API、数据库或 Agent 权限。

## 1. 具体问题与约束

维修已有完整工作台，招商客户与签约交接却放在弹窗中。招商已包含客户草稿、回访任务和历史，交接已包含联系单与版本快照，不再适合用一个短操作弹窗承载。关闭弹窗还会重置部分状态。

飞书是员工主要入口，Web承担运营管理、流程追踪和演示。工作区按业务任务划分，不能将导航菜单数量当作自主多 Agent 的实现证据。现有中文注释、已保存数据和正在运行的内存演示后端须保留。

## 2. 备选与取舍

| 方案 | 本项目收益 | 成本与限制 | 结论 |
| --- | --- | --- | --- |
| 继续用弹窗 | 改动较少 | 长流程拥挤，无独立地址，容易丢失临时状态 | 不采用 |
| Vue Router | 适合嵌套路由、详情地址和守卫 | 本轮只有三个平级页面，增加依赖及迁移范围 | 后续出现详情路由或权限守卫时重新评估 |
| 原生 hash 导航 + Vue 工作区组件 | 无新依赖，支持直接地址和前进后退，不要求部署端配置路径回退 | 需要自行处理 hash 与组件状态同步；暂不承担权限路由 | 本轮采用 |

以上为本项目范围内的取舍，不是对路由框架能力或性能的比较结论。

## 3. 决定及原因

采用 `#/repairs`、`#/investment`、`#/handoffs` 三个平级地址。导航状态集中在 composable 中；招商提取为独立组件，复用已有交接组件。首次进入才挂载招商与交接，此后通过 `v-show` 保留组件实例，避免来回切换卸载表单。

## 4. 架构与边界

- App负责导航、公共状态提示及维修工作区；招商组件负责客户草稿、客户列表与回访，交接组件负责联系单与交接记录。
- 模块切换只更新页面状态和地址，不创建业务对象，不触发模型分析或人工确认动作。
- 重新进入交接时只更新列表，保留正在编辑的联系单与意见；已有提交按钮仍通过业务 API 执行。
- 草稿保留限于同一页面实例内的模块切换，不等于刷新或浏览器关闭后的持久化；不向 localStorage 写入客户资料或凭证。
- 新建工单与报修初审保持现有操作弹窗。本轮不新增全局 AI 侧栏，不将页面重排表述为新增 Agent 能力。
- 后端服务、正式数据库、迁移脚本和环境密钥不在修改范围内。

## 5. 实施及退出方案

先拆招商组件，再接平级导航与响应式样式，保留现有 API 和人工门禁。使用前端类型检查和构建验证；可用时通过浏览器检查导航、草稿保留和窄屏布局。若以后需要客户详情链接、嵌套页面和登录守卫，再迁移至 Vue Router，并保留旧 hash 入口兼容。

## 6. 验收证据

- `npm run build`：Vue TypeScript 检查和生产构建通过。
- 用 Vue 自定义宿主挂载实际组件 setup，并以合成 GET 响应验证：招商原始输入、模型草稿、回访内容以及交接单、企服意见、签约勾选在工作区往返后保留；重新进入可刷新列表。
- 导航检查覆盖直接 hash 地址、切换、模拟浏览器 hashchange、已访问工作区集合和卸载后监听清理。三个工作区的服务端模板渲染均匹配标题，且只有一个导航项标记为当前页。
- 以上检查不调用真实模型，不发送业务写入请求，不代表真实浏览器点击验收或视觉验收。
- 通过用户当前5174代理读取客户、回访和交接列表均为200；1号工单仍为 `completed`，新版前端模块加载200。后端未重启。
- 浏览器控制通道返回 `browser.user is unavailable`；本轮桌面/手机实际布局与点击暂未验证。详见[工作区改版验收](../verification/Web工作区改版.md)。

## 7. 负责人参与点

用户已明确同意维修协同、招商客户、客户交接平级。完成后由用户重点 review 命名及招商到企服交接是否易于理解；不需要逐项批准组件拆分。
