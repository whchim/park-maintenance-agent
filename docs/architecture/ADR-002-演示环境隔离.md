# ADR-002：页面联调使用独立内存演示环境

- 日期：2026-11-01
- 状态：已实施并完成隔离演示验证
- 范围：本机页面联调与演示；不更换正式数据库和业务架构。

## 问题与选择

需要验证真实页面、API、Agent 和人工确认之间的交互，但用户要求保留现有业务数据、不执行数据库迁移。复制现有库仍涉及资料和旧结构；直接使用现有库无法隔离操作；另建磁盘演示库需要管理文件路径和清理。选择独立 SQLite 内存库，与现有测试使用同一隔离方式，预置明确标记的模拟人员，重启即重新开始。

演示启动器创建新的 FastAPI 实例，复用现有路由与 Service，通过依赖覆盖将请求的 Session 指向内存库；只在新实例的生命周期中创建演示表。原 `app.main:app`、现有数据库、迁移脚本和 `.env` 不修改。演示端口独立，固定监听本机回环地址，单进程运行，不开启 reload 或多 worker。

## 边界与代价

- `create_all` 仅作用于新建的内存引擎，不是对现有数据库执行迁移。
- 页面持续显示隔离演示标识和“重启后清空”，防止用户误认为数据已正式保存。
- 默认强制规则模式；显式 `--online` 且配置齐全才使用真实模型。内存数据会发送给模型，因此只输入模拟业务资料。
- 数据依赖进程存活，不适合生产、多人并发或持久化演示记录；重启丢失的是演示数据，现有数据不受影响。
- 图片联调观察到并行读取在StaticPool共享连接上相互干扰，演示Session依赖增加每实例互斥锁，整个请求使用连接期间串行化，避免其他Session关闭时回滚同一连接。只作用于内存演示，不改变正式数据库的连接策略；增加并行HTTP回归验证。演示请求可能排队，不代表生产吞吐能力。
- Web 流程以 `channel=web` 进入统一流程 API；飞书适配保持独立，页面不声称真实飞书已接入。
- 这不是正式鉴权、权限验证或生产部署方案。真实模型可能失败，页面按实际模式显示，不伪造成功轨迹。

## 验证与退出

已验证两次启动数据互不共享、正式引擎未连接、演示状态明确、补项前不能建单、确认后才能建单、生成建议不分派、Web 交接事件来源准确。后端完整离线回归138项通过，前端类型检查及生产构建通过。真实千问浏览器操作已走通企服追问、补项、人工建单和工程工具建议，停在人工分派前；截图、计量和启动方式见[页面联调与演示](../verification/页面联调与演示.md)。正式库兼容性与完整维修闭环不在本次验证范围。

停止演示进程后恢复原有启动方式即可退出，不需要迁移或回滚现有业务数据。正式数据库联调仍需单独准备和确认增量迁移。

## 负责人参与

2026-11-01入口升级补充：前端热更新连接旧内存进程时会出现新增路由404/405。为保留用户已推进的模拟工单，增加限定公开报修快照，恢复到新的空内存实例后校验再切代理，旧进程保留。不是正式库备份或全量迁移；导出范围不足时拒绝，不推断缺失记录。本次156项测试及5174 HTTP验证见[修复记录](../verification/5174接口版本修复.md)。

用户核对追问和工程推荐理由，并亲自选择正式分派人；演示建单的自动化检查只针对隔离数据，不替代真实业务授权。

依据：用户的数据保留约束、现有 FastAPI 依赖注入和内存数据库测试；没有引入新框架或新增运行依赖。
