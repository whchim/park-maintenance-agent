# ADR-009：Web操作后的飞书工程状态同步

- 日期：2026-11-01
- 状态：已实现，260项回归通过；本人重新查询已确认负责人和状态一致，真实验收通过
- 依据：用户在Web将3号分派ENG-DEMO-002并开始维修，飞书“派工 3”因pending限制返回通用错误；本人飞书仅绑定ENG-DEMO-001。

## 决定

沿用同一业务后端。派工查询先读真实状态：已有分派或不再pending时展示负责人、中文状态及明确操作范围，不重复生成派工建议或写入分派。负责人可查看已分派任务；维修操作仍限当前分派人员，不能因同一人演示多个角色就自动绑定其他人员。

扩展现有30秒扫描，将观察到的工单/分派/维修快照变化写入独立工程同步任务，由原工程工作线程更新卡片。同步仅GET业务API，渠道落盘，不改业务数据；快照与身份配置去重。Web分派给已绑定维修员时自动展示当前任务卡；未绑定时明确通知负责人继续在Web办理或由管理员显式建立映射。旧维修员的卡片只读、旧nonce和材料上下文失效。同步展示processing卡片不自动切换用户当前材料归属，需本人发送“维修 ID”选择。

## 备选与边界

业务事件事务外发是生产目标，但当前8003不能重启、不能新增业务表迁移，先采用读取快照的增量同步。它只反映扫描时最新状态，不声称捕获两次扫描间的所有中间事件；原业务事件仍由后端保存。已完成旧任务只更新已知卡片，不向未参与账号广播历史数据。停止reminders时停止周期同步，显式查询仍读取最新状态。

通知把可输入命令单独列出。复制旧通知说明尾缀的“派工 3”允许只读查询；含糊维修提交、未知指令不自动执行业务。错误提示必须区分状态变化、当前维修员不匹配、未绑定渠道和真正接口失败。

## 验证

覆盖Web仅分派、已接单/处理中、未绑定维修员、已绑定维修员、改派及旧按钮/上下文失效、完成卡片、重复扫描、同步无业务写入、复制通知尾缀。保留原8003和3号分派，只重启桥接；真实状态通知由本人验收，不改派到001或擅自更换绑定。

实施结果：新增10项隔离API用例，最终后端260项通过，SDK自身2项弃用提示。仅重启桥接，保持reminders及招商owner绑定；实际鉴权、长连接connected通过。首次扫描产生2条同步任务并全部done：更新既有2号已关闭任务卡，并向负责人发送3号当前状态卡。3号最新输出sent，包含processing中文状态、ENG-DEMO-002和未绑定提示，无操作按钮；原新单提醒账本仍只有1条sent。重启前后3张工单、2个客户、2份交接及当前流程公开API内容hash逐项一致。本人重新查询后确认“显示正常，负责人和状态一致”；只读账本核对查询任务done、最新输出sent且更新既有卡片，3号视图仍1个、sync仍2条done。002的真实飞书维修操作仍需显式绑定，详见[修复记录](../verification/20261101-Web飞书状态同步修复.md)。
