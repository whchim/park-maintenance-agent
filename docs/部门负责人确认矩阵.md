## 签约客户交接实施记录

本轮依据白皮书第七部分 7.2，将客户交接落实为独立业务对象 `CustomerHandoff`，不使用维修工单承载。

- 新录入意向客户只生成建档事件 `investment.lead.confirmed` 和回访任务，不再自动产生正式客户交接。既有历史事件保留，不据此认定客户已签约或企服已接收。
- 状态路径为：招商草稿 → 招商确认签约并提交 → 企服接收；也可由企服退回 → 招商修改后重新提交。接收和退回均需填写意见，已接收记录不能继续修改。
- 当前演示字段包括合同编号/版本、最终版联系单引用/版本、入驻位置、联系人、联系方式、服务需求和约定事项。完整性检查只检查必要字段是否填写，不核验合同效力、文件真实性或业务内容准确性；正式字段以负责人提供的标准单为准。截图、手写变更不作为正式模板的替代依据。
- 招商每次提交后的联系单被冻结；重新编辑需先由企服退回。每次提交、接收和退回都保留操作人、时间和文档快照，原提交部门的记录不会被后续修改覆盖。
- 招商确认签约时，将客户阶段改为 `signed`，取消未完成的意向回访任务并保留历史记录。交接状态、客户阶段、回访任务和事件在同一事务提交，失败一起回滚。企服退回资料不会将已签约客户改回意向客户。
- 操作人目前是页面填写的演示身份，不具备登录鉴权和部门权限验证。联系单检查模式明确标记为 `rule_fallback_demo`，不代表已经接入真实 LLM 或自主多 Agent。
- 前端新增“客户交接”弹窗，可选择客户、保存检查草稿、确认提交、企服接收/退回和查询版本快照。`revision` 是防止覆盖他人修改的技术版本号，与合同及联系单的业务版本号分开。
- 新表已纳入 `backend/migrate_business_agent_tables.py` 增量脚本；本轮未执行迁移、未修改现有业务数据。现有数据库需完成迁移后再进行页面联调，构建通过不等于现有环境已可演示。
- 验证结果：独立内存数据库覆盖缺项、未确认签约、误用报修接口、提交冻结、退回重提、历史快照、过期版本、重试幂等、跨交接单幂等键冲突、签约后停止回访和事务回滚。后端全套 **91 项通过**，前端类型检查与生产构建通过。

### 联调时由用户参与的验收

在单独确认并完成数据库增量迁移后，用演示客户进行以下操作：

1. 新建意向客户，确认只出现回访任务，未自动进入企服交接队列。
2. 打开“客户交接”，选择客户并打开草稿；故意缺少合同编号，检查提交被阻止。
3. 补齐并保存，人工确认签约后提交；确认待回访任务停止，交接状态为待企服接收。
4. 以企服身份填写具体原因并退回，招商更正入驻位置和联系单版本后重提。
5. 企服确认接收，查看首次提交与更正后快照，确认历史内容仍能追溯。

正式上线前仍需业务负责人提供标准联系单，并确认字段和身份权限；本轮不替负责人编造这些制度。
