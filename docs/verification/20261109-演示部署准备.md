## 模型费用边界

在模拟供应商传输层、临时SQLite账本下验证：

- 日额度达到上限后不进入供应商传输函数，结构化和工具调用都回退为daily_budget_exceeded。
- 工具请求在配额阻止时request_attempted=false，不虚增供应商调用计数。
- 网络失败仍占已预留次数；错误配置、不可写账本均拒绝远端调用。
- 第三个同时模型请求返回model_busy，不消耗配额。
- 分钟额度跨调用保留，下一固定分钟窗口恢复；过往日期不占用当日额度。
- 没有配置部署额度的原本机入口行为不变；部署入口要求正整数配额和独立账本。

未执行实际付费模型请求。日/分钟额度是请求次数而非人民币预算，真实模型效果、供应商账单和额度告警需另行验收。

## 发现并修复的问题

- 部署路由初版按APIRoute类型筛选，遗漏当前FastAPI版本的嵌套include_router，导致附件404；已保留嵌套路由，仅排除文档入口，临时库及真实容器均复验成功。
- 测试脚本首次通过非交互stdin生成密码时认证未通过；改为仅本机一次性随机测试口令明确生成哈希，随后鉴权与完整流程通过。正式部署说明使用交互输入，不将真实明文口令放进命令参数。
- 自定义鉴权中间件方案被自动审批拒绝；没有绕过拒绝写入该中间件，最终使用Caddy内置Basic Auth，实际验证其访问边界。

## 保留边界

- 公网服务器、真实域名HTTPS、外网防火墙和长期运行尚未验收。

- 飞书桥接仍要求原本机隔离演示入口，本轮不支持自动转为云端桥接。
- 单后端实例、SQLite与工单编号仍有限制，不宣称高并发；没有全面安全审计或负载测试。
- 容器构建使用现有依赖范围；npm安装提示3项moderate依赖告警，本轮未自动升级依赖，不将构建通过等同于无漏洞。

## 复现

先在项目根目录构建测试镜像：

```sh
docker build --target backend -t park-portfolio-backend:verify .
docker build --target gateway -t park-portfolio-gateway:verify .
```

在安装项目后端依赖的Python环境中运行：

```sh
python backend/scripts/verify_deployment.py
```

该脚本只用于本机临时验收，不用作公网服务启动入口。部署命令及备份流程见[部署说明](../../deploy/README.md)。
