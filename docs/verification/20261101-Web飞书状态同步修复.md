# Web派工后的飞书状态同步修复 · 2026-11-01

## 问题与实际状态

用户截图显示复制通知整段说明后收到格式错误；随后“派工 3”收到通用失败。只读核对发现WX202611010003已在Web分派给ENG-DEMO-002水电维修模拟员，并完成接单/开始，状态processing。本人飞书绑定的是ENG-DEMO-001，不能自动冒用002。

根因：dispatch_card仅接受pending，即使Web操作合法也返回pending_ticket_required，而异常提示没有解释状态；自动提醒仅通知新单，没有同步Web形成的分派与后续进度。旧通知把可输入命令和解释放在同一行，用户容易整段复制。

## 修复范围

依据[ADR-009](../architecture/ADR-009-Web与飞书工程状态同步.md)：

- 派工查询先读业务状态。已有分派或后续状态展示当前负责人/进度；本人确为当前维修员时进入自己的任务卡，否则只读。查看权限不扩展为维修权限。
- 新通知把命令单独列出；复制旧说明尾缀也可作只读查询，关键写入仍需卡片确认。未知工单、格式错误及状态变化分别提示。
- 现有30秒扫描把工单、分派和维修快照变化写入独立工程同步任务，工作线程更新卡片；已绑定维修员收到当前任务，未绑定则负责人收到明确说明，继续在Web办理或由管理员显式配置身份。
- 旧维修员卡片与按钮失效，已完成任务卡显示企服已关闭；同步processing不自动选择材料所属工单，需本人发送“维修 ID”。
- 快照和身份配置去重，在途旧快照不重放；先发送上一工程任务已经准备好的输出，避免未绑定消息ID的卡片重复创建。

没有改派3号、没有把本人绑定到002、没有重启8003或迁移业务库。同步本身只GET业务API，不用模型推断状态。原始失败消息保留，不自动重放。
