# 返工操作反馈修复

日期：2026-11-09。

## 定位与改动

用户反馈“退回工程部返工没有用”。检查时线上工单1仍为pending_review，验收历史为空，访问日志未发现验收POST。代码确认空白意见会在前端直接拦截，原错误提示位于页面上方，操作区附近没有说明。不能据此断言用户当时输入内容，但可确认该反馈路径有缺陷。

拆出AcceptanceForm组件：明确标注意见/退回原因必填，缺少原因时在输入框下方显示校验提示并聚焦文本框；请求失败同样在表单内展示。增加退回后状态与历史保留说明、提交中反馈和禁用控制。父组件接收明确的布尔accepted值，沿用原接口与刷新逻辑。组件按工单及验收状态挂载，切单或成功退出待验收后清空上一轮输入。

## 验证

- `npm run test:acceptance-form`：4项通过，覆盖空白拦截与聚焦、退回发送false/原因/操作人、通过发送true、提交中阻止重复操作、模板错误及忙碌提示。
- `npm run test:acceptance-history`：2项通过。
- `npm run build`：类型检查和构建通过；`git diff --check`通过。
- 从当前运行数据库复制临时副本验证：退回201 → processing、清空submitted_at、保留责任人与原维修记录 → 再次维修201 → 验收通过201 → completed，历史保留false/true两次结果。测试强制规则模式，不调用模型，副本已清理。
- 实际工单1保持pending_review，未替用户提交意见或退回。浏览器工具因沙箱启动失败，未完成真实浏览器点击与视觉验收；组件行为与副本API验证不等于浏览器端到端验收。
