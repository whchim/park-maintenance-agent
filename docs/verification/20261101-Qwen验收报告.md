## 发现并修复的问题

首次整轮中企服两项通过，工程完成了两次查询，但最终输出未通过结构校验；保留 [首次未通过报告](./online-20261101-attempt-1.json)。随后仅运行工程的定位调用又观察到最后一轮仍请求查询，系统按预算停止。

修正为：前面的模型决策仍可选择工具或提前回答，最后一次请求停止提供工具，明确使用 JSON 对象输出模式形成建议。仍最多3次模型请求；缺证据、未知人员、越权工具和非法字段继续拒绝。修正后的完整证据见 [在线通过报告](./online-20261101-attempt-2.json)。没有把首次失败改写成成功，也没有将规则回退视作模型通过。

架构执行策略已回填 [ADR-001](../architecture/ADR-001-LangGraph.md)。新增验收脚本和相关边界测试后，后端全套 **133 项离线测试通过**。

## 用户参与的评审

请对照在线通过报告核对三个业务判断：

1. 只说“漏水”时是否确实需要追问位置，追问是否清楚。
2. “漏水；位置在A栋302”的提取依据是否来自原话，信息齐全后是否应该交给人工确认。
3. 工程推荐理由是否足够支持负责人判断，是否还缺需要追问的资料；当前模拟人员、技能和区域不是园区事实。

自动验收覆盖协议、证据存在、合法编号、执行预算和人工门禁；不能证明自然语言理解完全准确。若后续有多名候选，应增加真实部门认可的对照用例，不能仅凭这一个人选场景评价派工质量。
