# 飞书新草稿与Web自动同步修复

日期：2026-11-01。选型依据：[ADR-010](../architecture/ADR-010-新报修续办与Web自动刷新.md)。

## 问题

截图中的单独“新报修”仅得到补充格式提示，实际没有创建新受理草稿、没有切换会话；因此随后位置说明和确认仍指向已完成3号。Web维修列表只在初始化及手工操作后刷新，飞书新建或办理不会主动刷新页面。“派工 新ID”被当作字面指令输入，属于录屏说明不够直观。

## 改动

- 单独“新报修/报修/新报修：”将用户原始消息作为新流程初始输入，立即建立缺项草稿并映射新会话；补项、人工确认后才建单，旧工单保持。
- 建单和进度回复显示数字工单ID；已有工单收到其他文字时明确提示该文字未作为新报修录入。查询与重复确认仍不重复创建。
- Web维修工作区每5秒、窗口聚焦、页面重新可见及切回工作区时只读刷新。静默刷新保留选择与未提交说明/图片，失败保留原展示并提示；请求序号与当前工单校验隔离过期结果。
- 录屏脚本去掉可直接误复制的“新ID”代码块，说明按实际返回数字发送。飞书草稿尚未人工确认时不出现在正式工单列表，这是预期行为。
