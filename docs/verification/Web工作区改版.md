# Web工作区改版验收（2026-11-01）

## 交付范围

- [维修协同](http://127.0.0.1:5174/#/repairs)：原工单列表、详情、图片和处理流程。
- [招商客户](http://127.0.0.1:5174/#/investment)：独立页面，包含意向草稿、人工建档、回访、客户档案列表与搜索。
- [客户交接](http://127.0.0.1:5174/#/handoffs)：独立页面，包含联系单、接收/退回及版本快照。
- 三个同级导航支持独立地址和浏览器前进后退；窄屏提供横向导航，避免原侧栏隐藏后无法切换。
- 新建工单和企服报修初审继续使用现有操作弹窗。没有新增全局AI侧栏，也没有增加自主多Agent能力。

## 已执行的验证

1. `cd frontend` 后执行 `npm run build`，Vue TypeScript检查和Vite生产构建通过。
2. 使用已安装的Vue、Vite和服务端渲染工具做临时运行时检查，未安装测试依赖、未提交测试框架。合成GET响应替代真实业务与模型请求。
3. 导航逻辑验证了初始地址、切换时hash更新、模拟hashchange回退、已访问工作区记录和卸载后的事件清理。
4. 实际招商组件setup中的意向原文、模型草稿、回访输入在active往返后保留，客户列表仍可更新。
5. 实际交接组件setup中的未保存位置、企服意见及签约勾选在active往返和列表刷新后保留。
6. 三个工作区的服务端模板渲染均匹配页面标题，仅一个导航项具有`aria-current="page"`，招商与交接不再生成原弹窗容器。
7. 从当前5174代理只读检查客户列表、回访列表、交接列表，均返回200；新前端模块加载200，1号维修工单仍为`completed`。

首次组件状态检查因临时检查器未提供Vite SSR上下文而失败；为检查器补充上下文后重新运行，四组检查均通过。该失败没有产生业务请求或数据变更。

## 验证边界

- 浏览器控制通道不可用，返回`browser.user is unavailable`。上述运行时检查和模板渲染不等于浏览器点击或桌面/手机视觉验收；本轮没有截图证明。
- 工作区草稿保留仅适用于同一页面实例中的模块切换；刷新、关闭页面或开发热更新仍可能丢失未保存表单。
- 未调用真实Qwen；没有代用户创建客户、完成回访、提交联系单或作出企服决定。
- 后端没有重启；没有修改业务API、执行数据库迁移或删除业务数据。原8001及当前8003演示实例保留。

## 用户参与的检查

1. 刷新5174一次，检查三个同级导航与页面标题。
2. 在招商意向文本中输入测试内容，切换到维修，再回招商，检查文本仍在。
3. 已有交接草稿可编辑时填写一处未保存内容和企服意见，切换模块后返回检查；不要把刷新页面视为保存。
4. 继续上轮招商草稿和客户交接业务验收；点击模型分析及正式确认仍由用户决定。
