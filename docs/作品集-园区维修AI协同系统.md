# 园区运维 AI 工作流：从自然语言到可控业务执行

**AI 应用开发案例｜个人项目 · 基于企业测试题持续迭代**

Python / FastAPI · Vue 3 / TypeScript · LangGraph · Qwen · SQLAlchemy / SQLite · 飞书 SDK

## 要解决的核心问题

自然语言报修往往缺少地点或必要说明，而模型给出的建议也不能直接视为事实或操作指令。本项目探索：如何将模型的理解能力接入真实可运行的业务流程，让结果可校验、操作需确认、异常可回退、过程可追溯。

**演示主线：** 一条“空调漏水”的消息，经缺项追问和人工确认生成工单；工程助手查询模拟人员目录及未结束分派数提出建议，负责人确认派单；维修提交后进入验收，未通过则返工并保留完整历史。

## 三个关键技术决策

- **用证据约束生成。** 模型输出经 Schema 及原文证据校验后进入业务流程；信息不足时补充采集，调用或校验失败时明确标记规则回退，避免将推测作为已知事实展示。
- **为 Agent 划定执行边界。** 使用 LangGraph 组织“模型决策 → 只读工具 → 继续判断”的循环；校验工具名称、参数和候选人员，限制单次请求与工具调用次数。模型只提供建议，业务写入由人工确认及服务层状态校验共同控制。
- **将 AI 推理与业务事务分离。** 工程建议通过独立只读请求生成，避免在建单写事务中等待模型；Web 与飞书复用业务服务，工单状态、维修凭证及验收历史由应用持久化。跨请求续办使用应用事件，不宣称已实现 LangGraph 原生中断恢复。

## 验证与交付证据

**290 项后端离线测试、6 项前端组件测试通过。** 覆盖工具参数约束、模型异常与配额回退、业务状态流转等场景；实际 Docker / Caddy 联调走通派单、维修、退回、再次提交及验收，重启后工单、历史记录和图片保留。

部署方案包含统一口令入口、独立数据卷，以及持久化的模型日 / 分钟请求配额和并发限制。提供数据库设计、架构取舍与验收记录，可结合代码说明实现及失败路径。

**项目边界：** 使用 AI 辅助编码及模拟业务资料；已完成本机容器验收，公网待部署。当前不具备正式组织权限体系，尚无真实业务规模和模型效果量化结论。
