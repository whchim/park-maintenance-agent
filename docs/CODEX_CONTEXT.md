最新补充（2026-11-01）：确定飞书为员工主要入口、Web为运营维护与演示入口，复用业务后端与附件服务。已新增报修/维修图片拖放与选择上传、预览、业务绑定及刷新回显；本机图片演示5175/8002，原5174/8001保留。后端155项、前端构建及依赖检查通过。新增附件表迁移脚本但未执行现有库迁移；真实飞书图片接入和AI识图未实现，原生文件拖拽手势需用户人工测试。见[ADR-003](./architecture/ADR-003-飞书入口与统一图片附件.md)与[图片上传验收](./verification/图片上传与飞书入口验收.md)。

- 开始任务先检查实际代码、测试、数据库结构和前端，不以文档替代代码事实。
- Agent 负责理解、分析和建议；业务 Service 负责校验、事务、状态流转和数据库写入。
- 关键动作保留人工确认，Agent 不直接写数据库或绕过状态机。
- 不删除现有业务数据，不重建 SQLite 数据库；数据库变更只能采用可说明、可验证的增量迁移。
- 保留已有中文注释和用户未提交的改动；修改前说明目标和风险。
- 不把固定函数调用、页面名称或 if/else 路由包装成自主多 Agent。
- 每个阶段运行相关测试，并说明已实现、待验证、计划实现和模拟数据的边界。
- 以中文解释关键技术取舍，避免只给代码不讲业务作用。
- 每次引入或替换架构方案先写选型报告，说明业务依据、备选、成本、边界及验证计划；完成后回填证据，模板见 `docs/architecture/TEMPLATE.md`。
